# LLM 概念：预训练模型、架构与注意力掩码

**原文对应：**[微信资料](https://mp.weixin.qq.com/s/6MjoiitEncAMyDLgqzrkug)第 5 张“LLM概念”、第 7 张“语言模型”，以及路线图中的架构分类。本章按知识问答重新归纳，不复制整页截图；解释这些条目所需的基础概念是补充内容。图号是公开图集顺序，不是原始 PDF 页码。

## 1. 什么是语言模型和大语言模型 {#llm-basics}

**语言模型学习文本单位之间的统计关系，用这些关系预测或表示语言。**“根据前文预测下一个单位”和“根据上下文补回被遮住的单位”是两种常见训练任务，不是所有语言模型都只能聊天。

例如，“今天的天气很”后面可以接不同内容。生成式语言模型计算下一步各个候选的分数或概率，再按生成策略选择一个。这是对工作过程的说明，不是某个模型的实测回答。

原文“语言模型”页使用了更严格的概率定义：经典语言模型为 token 序列分配概率。对自回归模型，一段序列的概率按概率链式法则分解：

$$
p(x_1,\ldots,x_T)=\prod_{t=1}^{T}p(x_t\mid x_1,\ldots,x_{t-1}).
$$

这里 $x_t$ 是第 $t$ 个 token，$T$ 是序列长度，连乘号表示把各步条件概率相乘；第一项没有先前 token，通常结合起始符号处理。完整的可变长度生成还需定义结束条件。**这一分解不要求各 token 相互独立。**

模型给某段文本较高概率，不等于认证它事实正确。BERT 类掩码预测学习的是另一种条件预测任务，也不能直接当作 GPT 式从左到右的序列概率计算器。

**LLM** 是 Large Language Model，即大语言模型。当代主流 LLM 使用深度神经网络，在大规模语料上训练。模型规模、数据和计算共同影响能力，不能只凭参数多就判断质量。[Hugging Face 模型基础](https://huggingface.co/learn/llm-course/chapter1/4)

| 名称 | 回答的问题 |
| --- | --- |
| AI，人工智能 | 研究怎样让计算机完成感知、学习、推理、规划等任务 |
| ML，机器学习 | 怎样利用数据或交互经验学习规律 |
| DL，深度学习 | 怎样用多层神经网络学习表示与计算 |
| LLM，大语言模型 | 怎样在较大规模下学习语言并用于相关任务 |

它们不是四个同级产品。机器学习是 AI 的重要方法，深度学习属于机器学习，当代主流 LLM 属于深度学习模型。[D2L 导论][d2l]

## 2. 预训练、微调和推理有什么区别 {#pretraining}

**预训练**先让模型从大量数据中学习较通用的表示和规律；**微调**在已有模型基础上，用特定任务或指令数据继续训练；**推理**使用模型处理输入并产生输出。

| 环节 | 输入与目标 | 参数是否更新 |
| --- | --- | --- |
| 预训练 | 大量文本及从文本构造的预测目标，例如预测后续 token | 更新 |
| 微调 | 特定任务数据或问答示例，使已有模型适应目标任务 | 更新全部或部分可训练参数 |
| 常规部署推理 | 一段新的输入文本，计算表示或生成回答 | 通常不更新 |

“自监督”并不表示没有训练目标，而是目标可以由数据本身构造。例如用“今天的天气”作为输入的一部分，把原文接下来的单位作为预测目标，通常不需要人给每个位置单独标注。

预训练模型不一定已经擅长按指令对话；给模型增加提示词、历史消息或检索段落，也不等于微调了权重。

## 3. 文本怎样进入模型 {#token-basics}

先分清三个连续但不同的步骤：

1. **Tokenization：**按 tokenizer 的规则把文本转换成 token 序列。Token 可能是字、词的一部分、字节片段或特殊符号，不等于“一个汉字”。
2. **Token ID：**把每个 token 对应到词表编号。编号用于索引，大小本身不代表语义远近。
3. **Embedding：**按编号取得模型中的数值向量，再交给后续网络计算。向量是一组有顺序的数，其维数属于模型配置。

传统中文“分词”关注词边界，模型 tokenizer 关注模型的离散输入单位，两者可能重合但不等价。原文另有“分词”专题，详细分类留在该专题，不把它混进 LLM 定义。

## 4. Encoder、Decoder 和 Transformer 是什么 {#architectures}

**Transformer 是一种神经网络架构。**它使用注意力等模块计算序列表示。“注意力”让一个位置根据其他位置的信息更新自己的表示；先理解信息能从哪里流来，再研究矩阵公式。[Transformer 原论文][transformer]

- **Encoder，编码器：**接收输入序列，计算包含上下文信息的表示。典型双向编码器可利用输入中前后两侧的信息。
- **Decoder，解码器：**用于按顺序生成输出。在典型自回归生成中，不能读取尚未生成的后续内容。
- **Encoder-Decoder：**先由编码器表示输入，再由解码器结合该表示生成输出。翻译和摘要是常见任务。

| 架构 | 常见代表 | 典型用法 | 不应推导出的结论 |
| --- | --- | --- | --- |
| Encoder-only | BERT、RoBERTa | 分类、序列标注、抽取式问答 | 不代表可直接作为自回归聊天模型 |
| Decoder-only | GPT 类模型 | 续写、生成式问答 | 不代表只能生成、不能完成分类 |
| Encoder-Decoder | T5 | 将翻译、摘要、分类等表达为文本到文本 | 不等于简单地把两个现成模型接起来 |

这是典型结构和用法，不是任务之间不可跨越的限制。模型结构、训练目标、训练数据以及具体任务的适配方式都要分别看。

## 5. 原文列出的预训练模型有哪些区别 {#pretrained-models}

原文列出 GPT、BERT、XLNet、RoBERTa、T5。它们适合用来比较预训练思路，不是“当前最新排行榜”；也不能把所有版本统称为开放权重模型。

### GPT：根据已有内容预测后续 token

GPT 是 Generative Pre-trained Transformer。以早期公开研究的 GPT 系列为例，核心是自回归语言建模：给定已经出现的 token，预测下一个 token，再继续生成。

**记忆重点：**从左到右的生成、因果注意力。模型能生成回答不意味着回答必然正确；对话产品通常还包含后训练、提示词、工具和安全控制。

### BERT：根据上下文恢复被遮住的内容

BERT 是 Bidirectional Encoder Representations from Transformers。它的典型预训练任务之一是 **MLM，Masked Language Modeling，掩码语言建模**：遮住部分输入位置，让模型利用可见的前后文预测原内容。[BERT 论文][bert]

**记忆重点：**双向上下文、文本表示。双向不等于在普通生成任务中可以偷看未来答案；BERT 的训练任务与 GPT 式续写不同。

### XLNet：改变概率分解顺序

XLNet 使用广义自回归预训练，通过不同的预测分解顺序学习双向上下文，并结合 Transformer-XL 的设计。[XLNet 论文][xlnet]

**记忆重点：**它不是简单地把句子的词随机打乱后交给普通 GPT，也不是普通 BERT 掩码填空。具体的排列目标和双流注意力在模型专题展开。

### RoBERTa：重新研究 BERT 的训练方式

RoBERTa 延续 BERT 类模型的基本方向，系统研究训练数据量、训练时长、批大小等选择对效果的影响。[RoBERTa 论文][roberta]

**记忆重点：**效果差异可能来自训练配方，而非换了一个完全不同的骨干网络。不能仅凭新模型名称判断结构变化。

### T5：把多种任务统一成文本到文本

T5 是 Text-to-Text Transfer Transformer，典型实现使用编码器-解码器。输入为文本、输出也为文本，例如翻译输出译文，分类输出类别名称；其预训练研究包含恢复被破坏的文本片段。[T5 论文][t5]

**记忆重点：**统一任务表达形式，不是“所有任务的输入输出原本就相同”。还要区分 T5 最终模型和论文中比较的其他架构。

| 对比项 | GPT 类 | BERT 类 | T5 |
| --- | --- | --- | --- |
| 典型结构 | 仅解码器 | 仅编码器 | 编码器-解码器 |
| 代表预训练思路 | 预测后续 token | 预测被遮住的 token | 恢复被破坏的片段 |
| 常见输出组织 | 按顺序生成 | 每个位置或整段的表示，再接任务输出 | 按顺序生成目标文本 |

“开源”需要进一步问：代码是否公开？权重是否可下载？许可证允许什么？数据与训练流程是否公开？论文存在或 API 可调用，不能替代这些判断。

## 6. Attention Mask 到底限制什么 {#attention-mask}

**Attention Mask，注意力掩码，规定一个位置在这次注意力计算中允许参考哪些位置。**它主要控制信息可见范围；不等于一定把那些输入 token 从文本中删掉。

先区分三个相似的词：

| 名称 | 用途 |
| --- | --- |
| 因果掩码 | 阻止位置参考序列中位于它后面的内容 |
| 填充掩码 | 避免补齐序列长度的 padding 参与不应参与的计算 |
| MLM 的遮盖 | 隐藏部分原始输入，构造需要预测的训练目标 |

**注意力掩码改变“看哪里”，MLM 遮盖改变“输入隐藏了什么、训练要预测什么”。**两者相关，但不是同一操作。

## 7. Prefix LM 和 Causal LM 有什么区别 {#causal-prefix}

原文提出了这个问题。这里按 [T5 论文 §3.2.1][t5-masks] 的单栈架构对比口径解释：核心区别是**已知前缀内部是否允许双向注意力**，不是有没有在提示词前面加一句话。

### Causal LM：各位置只能参考自身及此前内容

输入位置按原顺序排列。计算第 2 个位置的表示时，可以参考位置 1 和 2，不能参考位置 3、4。训练时即使完整序列都已提供，也要限制后续内容泄漏。

### Prefix LM：前缀双向可见，生成部分仍然因果

把序列分成已知输入前缀和待生成部分。前缀内部各位置可以互相参考，但不能读取目标部分；目标部分可以参考整个前缀及已经出现的目标内容，不能参考后续目标内容。

### 用四个位置直接对照

假设 `P1、P2` 是两个前缀位置，`T1、T2` 是两个目标位置。下面是**本手册按上述规则制作的可见性示意**，不是运行模型获得的注意力权重。

行表示正在计算的位置，列表示可以参考的位置；`1` 为允许，`0` 为禁止。

**Causal LM**

| 当前位置 | P1 | P2 | T1 | T2 |
| --- | --- | --- | --- | --- |
| P1 | 1 | 0 | 0 | 0 |
| P2 | 1 | 1 | 0 | 0 |
| T1 | 1 | 1 | 1 | 0 |
| T2 | 1 | 1 | 1 | 1 |
{: #causal-mask .intro-table }

**Prefix LM**

| 当前位置 | P1 | P2 | T1 | T2 |
| --- | --- | --- | --- | --- |
| P1 | 1 | 1 | 0 | 0 |
| P2 | 1 | 1 | 0 | 0 |
| T1 | 1 | 1 | 1 | 0 |
| T2 | 1 | 1 | 1 | 1 |
{: #prefix-mask .intro-table }

最直接的差别是第一行：Prefix LM 的 `P1` 可以参考已经给定的 `P2`。两种方式都不允许前缀读取目标，也不允许 `T1` 读取未来的 `T2`。

**为什么对角线允许参考自己，不算泄漏答案？**这两张表描述的是输入位置表示；典型下一 token 预测会把标签错开一位。`T1` 已作为输入时，该位置用来预测后续目标，而不是复制 `T1` 作为自己的未知答案。预测第一个目标前，输入中不能已有它的真实内容。

**Prefix LM 是否就是 Encoder-Decoder？**不是。这里的 Prefix LM 使用同一个 Transformer 层堆栈，通过掩码区分前缀与目标；标准 Encoder-Decoder 有编码器、解码器及它们之间的注意力连接。相似的信息可见范围不代表网络结构完全一样。

原文举出 UniLM、GLM 等例子。[UniLM][unilm]通过不同掩码组织单向、双向和序列到序列任务；[原始 GLM][glm]研究自回归空白填充。应按具体论文、版本及任务说明，不能把整个 GLM 系列的后续版本都归为同一种 Prefix LM。

## 8. 容易混淆的概念 {#misconceptions}

| 问题 | 结论与边界 |
| --- | --- |
| BERT 和 GPT 都是 Transformer，是否等价？ | 不等价，典型结构、掩码与训练目标不同 |
| Prefix LM 就是给 GPT 加前缀提示词吗？ | 不是；文本前缀不自动改变注意力掩码 |
| 有参数就一定是大模型吗？ | 不是，参数是可学习数值，规模要结合具体模型讨论 |
| 输入里出现新资料，是否已经训练？ | 常规推理中它只是上下文；参数更新是另一件事 |
| 基础模型等于 LLM 吗？ | 不等于；基础模型强调广泛预训练及多任务适配，也可涉及其他模态 |
| 生成式 AI 等于文本 LLM 吗？ | 不等于，生成内容还可以是图像、音频等 |

基础模型的概念见 [Stanford CRFM 报告][foundation-models]。应用中的历史记录、检索库属于外部状态，不能和模型参数混为一谈。

**与 Agent 的关系：**LLM 是模型，RAG 是检索与生成的组合，Agent 还涉及工具、状态和执行控制。它们不是互斥型号，也不是本章要提前完成的工程内容。相关内容分别保留在 [M11]({{ '/roadmap/' | relative_url }}#m11) 与 [M12]({{ '/roadmap/' | relative_url }}#m12)。

## 9. 面试问答与自查 {#interview}

### 如何比较原文的五种预训练模型？

先讲训练目标和结构：GPT 类侧重自回归生成；BERT 使用双向表示与掩码预测；XLNet 改变自回归分解顺序；RoBERTa研究 BERT 的训练配方；T5 使用文本到文本框架及编码器-解码器。之后再比较具体版本、数据与评测，不能只比较名称。

### 一句话说清 Prefix LM 与 Causal LM？

两者都可因果地生成目标，但 Prefix LM 允许已知前缀内部双向可见；纯 Causal LM 的前缀内部也保持因果约束。

### 自查：Prefix LM 的前缀位置能看到真实目标吗？

不能。对照表中前两行的目标列都为 0。只说“前缀双向”而忘记前缀不能看到目标，会造成答案泄漏。

### 掌握到什么程度再往下走？

能够区分结构、训练目标、注意力掩码和模型权重；能解释上面两张表的每一行，不必现在推导完整注意力公式。
