# AI、机器学习、深度学习与大模型的关系

**先修要求：**不需要训练过模型，也不需要 GPU 或模型 API。

**本章目标：**遇到一个 AI 产品时，能分清它要解决什么任务、用了什么模型、模型如何学到能力，以及模型之外还有哪些系统组件。

## 1. 先把四个概念放在正确的位置

AI、机器学习、深度学习和大语言模型不是四个可以相互替换的产品名称。它们描述的范围不同。[《Deep Learning》导论][deep-learning-book]和 [D2L 导论][d2l]提供了理解这种关系的基础。

| 概念 | 本章采用的理解 | 不应混淆的边界 |
| --- | --- | --- |
| 人工智能，AI | 围绕感知、推理、学习、规划和决策等能力的研究与工程领域 | 不只包括神经网络，也包括搜索、规则和知识表示等方法 |
| 机器学习，ML | 用数据或交互经验构建、调整模型，使其在某类任务上获得能力 | 不是每遇到一条输入就自动更新参数，也不是所有 AI 方法都必须学习 |
| 深度学习，DL | 机器学习中的一类方法，通过多层可学习表示组织计算 | 不等于所有机器学习，也不只处理语言 |
| 大语言模型，LLM | 在较大规模数据、参数与计算条件下训练的语言模型；当代主流实例采用深度神经网络 | 不是 AI 的全部，也不是完整应用系统；“大”不宜硬套一个永久统一的参数门槛 |

用入门层面的包含关系记忆：**深度学习属于机器学习，机器学习是实现 AI 的重要路径之一；当代主流 LLM 是深度学习的一个重要应用。**

这不是一条替代关系。出现了 LLM，不意味着线性模型、树模型、CNN、搜索算法和确定性程序都失去价值。

“模型”也不等于“学习算法”：模型用于计算输入到输出的映射，学习算法用于根据数据调整模型。神经网络的结构和训练它的优化器，是不同层面的对象。[D2L §1.1–1.2][d2l]

## 2. 用同一个任务比较规则、机器学习和深度学习

假设需要把一条客服工单分到“支付”“配送”“账户”等类别。以下是**原创教学场景，不是实际客户数据，也不代表任何准确率测量**。

### 方案一：工程师编写规则

例如：文本同时包含“付款”和“失败”时，进入支付队列；其他情况交给人工。

这里的判断方式由人直接写入程序，没有通过训练数据拟合参数。规则可以是 AI 系统的一部分，但不能把任何一个 `if` 都称为机器学习。

它的取舍也很清楚：规则容易审计，但同义表达、否定、上下文和不断变化的业务会增加维护成本。若任务可以被稳定规则准确描述，并不必然需要模型。

### 方案二：从历史工单学习一个分类器

工程师准备带类别标签的工单，选择特征表示、模型和训练方法，让模型根据数据调整参数。比如，将词频特征交给一个线性分类器。

工程师仍然要决定任务、数据、目标和评测方法；“从数据学习”不等于取消工程设计。这个方案属于机器学习，但没有因此成为深度学习。

### 方案三：使用深度神经网络

使用多层神经网络学习文本表示和分类关系，可以减少部分手工特征设计。实际方案可能从已有预训练模型出发，也可能在适合的条件下从头训练。

变化发生在模型与表示学习方式上，任务仍是分类。**不是只有生成长文本，才算使用了深度学习。**

### 方案四：让已有 LLM 输出类别

给模型提供类别定义、工单和输出格式，得到一个类别。即使没有为这个任务微调，模型本身也已经经历过训练；不能把“我没有训练它”理解为“它不需要训练”。

选择哪种方案，需要比较数据、成本、延迟、隐私、错误代价和评测结果。不能仅凭“模型更新、更大”断言它最适合这个任务。

## 3. 一次学习过程包含什么

[D2L §1.2][d2l]把核心组成归纳为数据、模型、目标函数和优化算法。用工单分类继续说明：

| 组成 | 工单例子 | 需要问的问题 |
| --- | --- | --- |
| 数据 | 工单文本及类别标签 | 标签可靠吗？是否包含隐私？是否代表将来的输入？ |
| 模型 | 从文本表示到类别分数的计算过程 | 结构和容量是否适合任务与资源？ |
| 目标函数 | 衡量预测与训练目标之间的差异 | 优化的目标是否与业务需要一致？ |
| 优化算法 | 根据训练信号更新参数 | 更新是否稳定？何时停止？ |
| 独立评测 | 在未用于训练的样本上检查效果 | 能否泛化？哪些类别和人群更容易出错？ |

最后一行不是训练四要素中的第五个参数，而是判断训练结果是否有用的必要环节。

只在训练数据上表现好并不够。模型可能记住了样本，也可能利用了上线时不存在的信息。训练集用于学习，验证集用于方案选择，测试集应保留作独立评估，不能反复看测试答案来挑方案。

因此，“训练 loss 下降”与“系统已经可用”之间，还隔着泛化、任务指标、运行环境和风险验证。

## 4. 训练、推理和上下文不是同一件事

**训练**是在选定目标下，根据数据或反馈调整模型参数。**推理**是使用模型处理输入、计算输出。常见部署推理中参数保持固定，但本章不把这当作所有在线学习系统的定义。

把一份说明书放进提示词，会改变本次计算可用的上下文；这本身不等于对模型进行了参数微调。

需要分清三种状态：

- **参数：**训练所改变的模型数值。
- **上下文：**本次推理可读取的提示、历史消息、检索内容等输入。
- **外部状态：**数据库、文件、应用记忆、工具返回结果等系统数据。

应用可以把聊天记录存入数据库，再在下一次请求中读取；这并不能证明模型在聊天中自动更新了权重。反过来，某个服务是否会将对话另作训练用途，要看该服务的数据政策，不能从技术机制推断。

## 5. 语言模型、大语言模型与基础模型

### 语言模型关心语言序列

语言模型对语言序列或其中一部分的概率关系进行建模。自回归语言模型的一种典型用法，是根据已有 token 预测下一个 token，再把生成结果接到上下文中继续计算。

Token 是模型的处理单位，不必对应一个完整词，也不必对应一个汉字。具体拆分取决于 tokenizer。分词、向量表示和注意力机制会在 M04、M05 中展开。

语言模型并非从 LLM 才开始，也不全是 Transformer。学习 NLP 时仍需要理解传统表示与语言建模方法。[Hugging Face LLM Course][hf-course]

### Transformer 是架构，不是 AI 的别名

[Attention Is All You Need][transformer]提出的是网络架构。架构如何组织计算，与用什么数据、目标和算法训练，是不同的问题。

只说“用了 Transformer”，还不能回答模型是编码器、解码器还是编码器-解码器，也不能确定它采用哪一种预训练或后训练过程。

### 基础模型强调可适配性

[Stanford CRFM 报告][foundation-models]用“基础模型”描述在广泛数据上进行规模化训练、能够适配多种下游任务的模型。

这个概念不只针对文本；报告讨论了语言、视觉等范围。它与 LLM 有很大交集，但二者不是同义词，也不代表模型已经适合任何具体业务。

“生成式 AI”则侧重生成内容的能力或系统用途，可以涉及文本、图像、音频等。不要把它机械地接在 AI → ML → DL → LLM 后面，画成另一层严格包含关系。

## 6. LLM、RAG 与 Agent 处在什么层面

这一节只划清边界，具体工程另见 M11、M12，不把基础课改成 Agent 框架教程。

| 名称 | 主要关注点 | 工单系统里的例子 |
| --- | --- | --- |
| LLM | 模型如何根据输入产生输出 | 给定工单与类别说明，生成分类结果或答复 |
| RAG | 如何将检索到的外部信息用于生成 | 检索当前退款政策，再根据证据起草答复 |
| Agent 系统 | 如何选择后续步骤、使用工具并根据结果继续执行 | 查询订单状态、检查权限、提出处理方案，必要时请求人工批准 |

[RAG 原论文][rag]结合了参数中的知识与外部检索内容，并研究了微调方法。因此，RAG 不能简单定义成“绝对不训练模型”；但仅把检索片段送入上下文，也不意味着已经更新参数。

Agent 没有一个所有团队都统一采用的严格边界。[Anthropic 的工程文章][agents]区分了预定义代码路径控制的 workflow，以及由模型动态决定步骤和工具使用的 agent。这里借用这种工程区分，不把它当作整个 AI 学科唯一的定义。

一个可靠系统还需要输入校验、访问控制、超时、失败处理、记录与评测。模型生成“已经退款”的文本，不等于业务系统真的完成了退款。

## 7. 六个常见误区

| 误区 | 更准确的理解 |
| --- | --- |
| AI 就是大模型 | AI 的方法和任务范围更广；大模型是其中的重要部分 |
| 机器学习就是深度学习 | 线性模型、树模型等也是机器学习方法 |
| 神经网络就是模拟完整人脑 | 人工神经网络是数学与计算模型，不应据其名称推断人类式机制 |
| 会流畅生成就等于掌握了事实 | 生成能力和事实正确性需要分开评估，不能由语气判断真实性 |
| 模型更大就一定更适合 | 需要结合任务、数据、预算、延迟和错误代价评测 |
| 聊过一次就永久学会了 | 当前上下文、应用持久化和参数更新是不同机制 |

## 8. 可核对练习：判断发生在哪一层

以下六个案例是人为编写的教学描述，不是外部服务的运行记录。无需安装软件或调用模型。

对每个案例回答：**有无从数据学习？能否判断属于深度学习？当前变化发生在参数、上下文还是应用状态？**

| 案例 | 描述 |
| --- | --- |
| A | 工程师手写报销规则，符合金额和类别条件才进入下一步 |
| B | 用标注工单训练词频特征上的线性分类器，然后预测一条新工单 |
| C | 用反向传播训练多层卷积网络，识别票据图像的类别 |
| D | 给参数固定的 LLM 加入三个分类示例，本次请求的输出发生变化 |
| E | 检索最新制度，把片段加入 LLM 上下文；不执行训练 |
| F | 应用将用户偏好写入数据库，下次调用模型前再读取 |

### 参考答案

| 案例 | 核对依据 |
| --- | --- |
| A | 没有从数据拟合模型；变化来自程序规则，不能据此称为机器学习 |
| B | 有机器学习；指定为线性分类器，不属于深度学习；训练改参数，预测使用已有参数 |
| C | 有深度学习；反向传播提供梯度，优化步骤据此更新参数 |
| D | 模型已有训练背景，但这次操作改的是上下文，不是参数微调 |
| E | 是检索增强生成的应用方式；这次变化在检索内容和上下文，不自动更新权重 |
| F | 改的是外部持久化状态；以后可被放进上下文，不能等同模型在线训练 |

**验收：**六个案例都能给出理由；尤其能区分 B 的训练与预测、D 的上下文与参数、F 的外部状态与模型记忆。若无法解释，回看第 3、4 节后重做。

## 9. 面试自测与参考回答

### 如何用一分钟解释 AI、ML、DL、LLM 的关系？

AI 是更大的研究与工程领域，机器学习是通过数据或经验构建能力的重要方法；深度学习属于机器学习，使用多层可学习表示。当代主流 LLM 是深度学习在语言建模上的重要实例，但 AI 不等于 LLM，完整应用也不等于一个模型。

**追问：不用深度学习能做 AI 吗？**可以。先说明具体任务，再举出搜索、规则推理或传统机器学习等方法；不要把所有普通自动化都贴上 AI 标签。

### 模型训练好，为什么还不能直接宣布系统成功？

因为训练目标和业务目标不完全相同。还需检查未见数据上的表现、错误类型、时延成本、权限和故障处理。训练集表现好并不保证泛化，模型文本正确也不保证外部操作成功。

**追问：测试集可以反复拿来挑方案吗？**不宜。这样会让方案选择逐渐适配测试集，削弱独立评估的意义。

### RAG、微调和 Agent 是互斥路线吗？

不是。微调关注参数调整，RAG 关注检索信息与生成的结合，Agent 关注任务执行控制。它们可以组合，但要分别评估收益、成本和失败模式。

**追问：把知识塞进提示词就解决幻觉了吗？**不能保证。信息可能缺失、过时、被错误检索或被错误使用，仍需验证答案是否受到证据支持。

## 10. 本章小结与下一步

- 先区分概念层级，再比较具体方法。
- 学习需要数据、模型、目标与优化；可用性还需要独立评测。
- 参数、上下文和外部状态不能混为一谈。
- 架构、训练方法和系统设计是不同维度。
- 学习 Agent 可以同步进行，但这些基础知识不能被框架调用替代。
